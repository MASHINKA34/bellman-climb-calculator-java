# Многополюсный поток - дерево Гомори-Ху

Приложение для Android считает **максимальные потоки между всеми парами вершин**
неориентированной сети. Сеть задаётся симметричной матрицей пропускных способностей
(по умолчанию 7 × 7). Расчёт идёт методом Гомори-Ху: строится дерево, по которому
читается поток между любыми двумя вершинами.

Написано на Java. Работает на Android 10 и новее, без интернета.

---

## Постановка задачи

Сеть неориентированная, поэтому матрица симметричная: `c(i, j) = c(j, i)` - пропускная
способность ветви между вершинами `i` и `j`, `0` - ветви нет.

Нужно найти максимальный поток между **каждой** парой вершин. Если считать каждую пару
отдельно, для 7 вершин понадобилось бы 21 вычисление потока. Метод Гомори-Ху обходится
**n - 1** вычислениями: для 7 вершин - шестью.

Для каждой рассматриваемой пары S, T записывается:

1. максимальный поток S → T;
2. разрез, разделяющий S и T;
3. ветвь дерева;
4. итоговая таблица: найденный поток вписывается в неё.

Итоговая таблица показывается в конце каждого шага и заполняется по ходу решения.
После последнего шага её остальные клетки заполняются по дереву.

## Алгоритм

1. В начале дерево - одна группа со всеми вершинами.
2. Берётся группа, в которой больше одной вершины (с самой маленькой вершиной),
   и в ней пара S, T - две её первые вершины.
3. Всё, что лежит за пределами группы, **стягивается**: каждая часть дерева, висящая
   на группе, становится одной вершиной (A, B, …), ветви к ней складываются.
4. Максимальный поток S → T считается **методом Форда-Фалкерсона**: пока от S до T
   есть путь с запасом, по нему пускается поток, равный самой слабой ветви пути.
   Пути ищутся, пока не исчерпаются; сначала самые короткие.
5. Вершины, до которых от S ещё можно дойти, - сторона S **минимального разреза**.
   Сумма ветвей разреза равна найденному потоку.
6. Группа делится разрезом надвое, половины соединяет новая **ветвь дерева** со значением
   потока. Ветви, висевшие на группе, остаются у той половины, на чьей стороне разреза
   оказалась их часть.
7. Шаги 2-6 повторяются, пока все группы не станут отдельными вершинами (n - 1 раз).

**Итоговая таблица.** На каждом шаге в неё вписывается поток найденной пары S, T - это
точное значение, дальше оно не меняется. Остальные пары известны только после последнего
шага: поток между вершинами `i` и `j` равен самой слабой ветви на пути между ними в дереве.
Значения по промежуточному дереву в таблицу не пишутся: пока группы делятся, на пути может
появиться ветвь слабее, и такое число оказалось бы завышенным.

От того, какие пары выбирать на шагах, может зависеть вид дерева, но не итоговая таблица.

### Литература

- Д. Филлипс, А. Гарсиа-Диас. Методы анализа сетей (МАС).
- R. E. Gomory, T. C. Hu. Multi-terminal network flows. Journal of the Society for
  Industrial and Applied Mathematics, 1961, 9 (4), 551-570.

```
│       ├── gomoryhu/GomoryHuSolver.java  ← сам алгоритм Гомори-Ху
│       ├── gomoryhu/Step.java            всё, что пишется на одном шаге
│       ├── json/SolutionJson.java        ответ для экрана
│       └── log/CoreLog.java              настройки логов ядра
├── ui/                      экран: index.html, styles.css, app.js, android-bridge.js
└── android/                 приложение для телефона
    └── app/src/main/java/ru/mashinka/multiflow/android/
        ├── MainActivity.java             экран с WebView
        ├── MultiFlowBridge.java          мост между экраном и ядром
        ├── MultiFlowApp.java             старт приложения, логи, перехват падений
        └── AppLog.java                   логи в logcat
```

Android-приложение не копирует ядро, а подключает те же файлы: в `android/app/build.gradle`
прописано `java.srcDir '../../core/src/main/java'`. Экран подключается так же:
`assets.srcDir '../../ui'`. Поэтому алгоритм и вёрстка существуют в единственном
экземпляре, а сайт (второй этап) соберётся из тех же файлов.

## Как собрать и проверить

Нужны JDK 17 или новее, Maven и Android SDK (platform 36). Путь к SDK -
в `android/local.properties`:

```
sdk.dir=C:/путь/к/Android/Sdk
```

### Тесты ядра

```bash
mvn test
```

Уровень логов в тестах - переменная `LOG_LEVEL` (`debug`, `info`, `warn`, `error`).

### Сборка APK

```bash
cd android
```

```bash
.\gradlew.bat assembleDebug
```

Готовый файл - `android/app/build/outputs/apk/debug/app-debug.apk`, около 100 КБ.

### Установка на телефон

На телефоне включить **Параметры разработчика → Отладка по USB**, подключить кабелем
и подтвердить запрос. Затем:

```bash
adb install -r android/app/build/outputs/apk/debug/app-debug.apk
```

APK можно и просто перекинуть на телефон и открыть - потребуется разрешить установку
из неизвестных источников.

### Логи

Все строки приложения, ядра и страницы идут в logcat под тегом `MultiFlow`:

```bash
adb logcat -s MultiFlow
```

Подробный уровень включается без пересборки, потом приложение нужно перезапустить:

```bash
adb shell setprop log.tag.MultiFlow DEBUG
```

## Проверка расчёта

В модуле `core` 25 тестов, среди них:

- на 500 случайных сетях от 2 до 10 вершин итоговая таблица совпадает с **полным
  перебором всех разрезов** - проверка, в которой нет ни строчки кода решателя;
- каждая ветвь дерева - минимальный разрез между своими концами;
- на каждом шаге сумма ветвей разреза равна потоку, а найденные пути складываются в поток
  и после них путей от S к T не остаётся;
- несвязная сеть, изолированная вершина, сеть из двух вершин;
- отказ на несимметричной матрице, отрицательных и слишком больших числах, пустой сети.
