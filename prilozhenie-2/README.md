# Многополюсный поток - дерево Гомори-Ху, размещение производства, транспортная задача

Приложение для Android, в нём три вкладки:

- **Поток** - **максимальные потоки между всеми парами вершин** неориентированной сети.
  Сеть задаётся симметричной матрицей пропускных способностей (по умолчанию 7 × 7).
  Расчёт идёт методом Гомори-Ху: строится дерево, по которому читается поток между
  любыми двумя вершинами.
- **Размещение** - **размещение производства**: какой новый вид продукции на каком
  предприятии выпускать, чтобы суммарная прибыль была наибольшей. Решается венгерским
  методом (задача о назначениях), подробно - [ниже](#вкладка-размещение).
- **Транспортная** - **транспортная задача**: математическая модель (открытая и закрытая) и
  начальный план методами северо-западного угла и минимальной стоимости, подробно -
  [ниже](#вкладка-транспортная).

Во всех вкладках таблицы можно не набивать вручную, а **заполнить по фото**: с камеры
или из галереи. Цифры распознаются прямо на телефоне, подробно - [ниже](#заполнение-по-фото).

Написано на Java. Работает на Android 10 и новее. Вход - **по ключу**: ключ открывает
выбранные вкладки на одном устройстве, выдаёт и отключает его владелец в админке, подробно -
[ниже](#ключи-входа). Расчёт идёт на телефоне, интернет нужен только для проверки ключа, без
связи приложение работает ещё три дня.

Есть и **сайт** с теми же вкладками - для айфона и компьютера, без заполнения по
фото. Экран и расчёт у сайта и приложения общие, подробно - [ниже](#сайт).

## Вкладка «Поток»

### Постановка задачи

Сеть неориентированная, поэтому матрица симметричная: `c(i, j) = c(j, i)` - пропускная
способность ветви между вершинами `i` и `j`, `0` - ветви нет.

Нужно найти максимальный поток между **каждой** парой вершин. Если считать каждую пару
отдельно, для 7 вершин понадобилось бы 21 вычисление потока. Метод Гомори-Ху обходится
**n - 1** вычислениями: для 7 вершин - шестью.

Для каждой рассматриваемой пары S, T на шаге три таблицы: **R** - сеть шага, **Xst** -
потоки по ветвям, **R - Xst** - что осталось после вычитания потоков. По ним записывается:

1. максимальный поток S → T;
2. разрез, разделяющий S и T;
3. ветвь дерева;
4. итоговая таблица: найденный поток вписывается в неё.

Итоговая таблица показывается в конце каждого шага и заполняется по ходу решения.
После последнего шага её остальные клетки заполняются по дереву.

### Алгоритм

1. В начале дерево - одна группа со всеми вершинами.
2. Берётся группа, в которой больше одной вершины (с самой маленькой вершиной),
   и в ней пара S, T - две её первые вершины.
3. Вершины **не стягиваются**: каждый шаг считается по всей исходной сети, таблицы шага -
   n × n, строки и столбцы 1…n по порядку, как на паре. Это способ Д. Гасфилда (1990):
   те же n - 1 расчётов потока, что у Гомори-Ху, но без склейки вершин в буквы.
4. Максимальный поток S → T считается **методом Форда-Фалкерсона**: пока от S до T
   есть путь с запасом, по нему пускается поток, равный самой слабой ветви пути.
   Пути ищутся, пока не исчерпаются; сначала самые короткие. После путей приложение
   показывает две таблицы, как в табличном методе на бумаге:
   - **Xst** - сколько потока пошло по каждой ветви: по направлению потока +f, в обратную
     клетку -f. Сумма строки S равна потоку, строки T - потоку с минусом, остальных - нулю;
   - **R - Xst** - таблицу после вычитания потоков: из каждой клетки R вычитается клетка Xst,
     то есть из c(i,j) вычитается пропущенный поток, к c(j,i) прибавляется.
5. Вершины, до которых от S ещё можно дойти по ненулевым клеткам этой таблицы, - сторона S
   **минимального разреза**. Сумма ветвей разреза равна найденному потоку. Сеть
   неориентированная, поэтому ветви разреза записываются меньшим номером вперёд: (2,6),
   а не (6,2) - как клетка над диагональю, куда матрицу и вводят.
6. Группа делится разрезом надвое, половины соединяет новая **ветвь дерева** со значением
   потока. Ветвь, висевшая на группе, остаётся у той половины, на чьей стороне разреза
   лежит первая (самая маленькая) вершина соседней группы - правило Гасфилда.
7. Шаги 2-6 повторяются, пока все группы не станут отдельными вершинами (n - 1 раз).

**Итоговая таблица.** На каждом шаге в неё вписывается поток найденной пары S, T - это
точное значение, дальше оно не меняется. Остальные пары известны только после последнего
шага: поток между вершинами `i` и `j` равен самой слабой ветви на пути между ними в дереве.
Значения по промежуточному дереву в таблицу не пишутся: пока группы делятся, на пути может
появиться ветвь слабее, и такое число оказалось бы завышенным.

От того, какие пары выбирать на шагах, может зависеть вид дерева, но не итоговая таблица.

### Литература

- Д. Филлипс, А. Гарсиа-Диас. Методы анализа сетей (МАС).
- R. E. Gomory, T. C. Hu. Multi-terminal network flows. Journal of the Society for
  Industrial and Applied Mathematics, 1961, 9 (4), 551-570.
- D. Gusfield. Very simple methods for all pairs network flow analysis. SIAM Journal on
  Computing, 1990, 19 (1), 143-155.

## Вкладка «Размещение»

### Постановка задачи

Компания выпускает `m` новых видов продукции и владеет `n` предприятиями (`m ≤ n`).
Каждый вид производится ровно на одном предприятии, на предприятии - не больше одного
вида. По умолчанию 3 вида и 5 предприятий, можно от 2 до 10.

Даны (все числа целые):

- издержки производства единицы продукции, руб. - таблица «вид × предприятие»;
- издержки сбыта единицы продукции, руб. - такая же таблица;
- плановый годовой объём каждого вида, ед.;
- плановая цена единицы каждого вида, руб.

Нужно разместить виды по предприятиям так, чтобы суммарная годовая прибыль была
наибольшей.

### Решение

1. **Общие издержки** на единицу = производство + сбыт.
2. **Прибыль на единицу** = цена - общие издержки (бывает отрицательной).
3. **Общая прибыль**, тыс. руб. = прибыль на единицу × объём / 1000.
4. **Сведение к минимуму.** Венгерский метод ищет наименьшую сумму, поэтому каждая
   прибыль умножается на -1 и к ней прибавляется наибольшая прибыль `M`: клетка = M - прибыль.
   Видов меньше, чем предприятий, - матрица дополняется до квадратной строками
   **фиктивных видов** с нулевой прибылью (в матрице - нули).
5. **Венгерский метод**, по итерациям:
   - шаг 1 (только на первой итерации) - из каждой строки вычитается её минимум, затем из
     каждого столбца - его;
   - шаг 2 - назначения по нулям: а) строки, где ровно один невычеркнутый ноль, б) такие же
     столбцы, а) и б) повторяются; назначение вычёркивает остальные нули своей строки и
     столбца. Если в каждой оставшейся строке по два нуля и больше - ноль выбирается
     (строка с наименьшим числом нулей, из равных - верхняя, в ней - левый ноль). Полное
     назначение - оптимальное;
   - шаг 3 - если назначение неполное: нули закрываются линиями (каждый раз строка или
     столбец с наибольшим числом ещё не закрытых нулей, из равных - строка раньше столбца,
     меньший номер раньше), из незакрытых клеток вычитается их минимум, к клеткам на
     пересечении линий прибавляется, и снова шаг 2.
6. **Ответ** - вид → предприятие, прибыль каждого и сумма. Предприятия, которым достались
   фиктивные виды, новую продукцию не производят. Если такую же прибыль дают и другие
   размещения, они перечислены (первые 20, счёт до 10 000).

Правила пособия иногда не срабатывают, и эти два случая решены так:

- правила шага 2 при неудачном выборе нуля могут не найти полное назначение, хотя оно
  есть. Тогда оно находится перебором нулей, а на экране об этом написано;
- правило «линия с наибольшим числом нулей» иногда проводит лишние линии, и тогда метод
  может ходить по кругу. Приложение в этом случае берёт наименьшее число линий: по
  теореме Кёнига оно равно наибольшему числу назначений. На экране это тоже отмечено.

На примере из пособия ни то ни другое не нужно: все шаги идут строго по книге.

### Встроенный пример и ошибка в пособии

Пример - из учебного пособия МЭСИ «Логистические модели», п. 3.2, пример 3.1
«Задача размещения производства». **В пособии ошибка.** В издержках производства на
предприятии 5 для видов 1 и 2 напечатано 5 и 5. Прибыль на единицу в книге посчитана по
этим числам (37 и -15), а матрица для венгерского метода и ответ - по числам **35 и 35**.
С напечатанными числами лучший ответ другой: 8137 тыс. руб. (вид 1 на предприятие 5).

В приложении стоят 35 и 35, поэтому весь пример сходится с книгой, от матрицы до ответа:

| Издержки производства | 1 | 2 | 3 | 4 | 5 |
|---|---|---|---|---|---|
| вид 1 | 20 | 23 | 38 | 15 | **35** |
| вид 2 | 8 | 29 | 6 | 35 | **35** |
| вид 3 | 5 | 8 | 3 | 4 | 7 |

| Издержки сбыта | 1 | 2 | 3 | 4 | 5 |
|---|---|---|---|---|---|
| вид 1 | 20 | 50 | 20 | 10 | 13 |
| вид 2 | 7 | 90 | 8 | 35 | 60 |
| вид 3 | 5 | 5 | 4 | 15 | 6 |

| Вид | Объём, ед. | Цена, руб. |
|---|---|---|
| 1 | 35 000 | 55 |
| 2 | 160 000 | 50 |
| 3 | 54 000 | 30 |

Решение: две итерации, как в книге. На первой назначено 4 из 5, нули закрываются четырьмя
линиями (строки 4ф, 5ф, столбец 3, строка 1), минимальный незакрытый элемент - 160.
На второй итерации назначение полное.

**Ответ:** вид 1 - предприятие 4 (1050), вид 2 - предприятие 1 (5600), вид 3 - предприятие 3
(1242); итого **7892 тыс. руб.** Предприятия 2 и 5 новую продукцию не производят.

## Вкладка «Транспортная»

Задание - контрольная «МАС. Транспортная задача»: 4 поставщика, 5 потребителей, 27 вариантов.
Нужно построить математическую модель (открытую и закрытую) и найти начальное решение
методами северо-западного угла и минимальной стоимости с общей стоимостью перевозки. Все 27
вариантов встроены (список «Вариант»), таблицу можно ввести и свою: от 2 до 10 поставщиков и
потребителей, числа целые.

### Математическая модель

Запасы равны потребностям - модель **закрытая**. Не равны - **открытая**, и для решения она
приводится к закрытой:

- потребностей больше - добавляется фиктивный **поставщик** (строка), запас - разница;
- запасов больше - добавляется фиктивный **потребитель** (столбец), потребность - разница;
- все стоимости фиктивной строки или столбца - нули.

Приложение пишет обе модели полной системой с числами варианта. В открытой модели у того,
чего не хватает, знак «=» (вывозится или закрывается полностью), у того, чего больше, - «≤».
В закрытой все ограничения - равенства. Запись модели - общепринятая, с пособием
преподавателя не сверялась.

### Начальный план

- **Северо-западный угол**: каждый раз заполняется левая верхняя из невычеркнутых клеток.
- **Минимальная стоимость**: каждый раз заполняется клетка с наименьшей стоимостью из
  невычеркнутых. Если таких несколько - та, куда помещается больше груза, из равных -
  верхняя, затем левая.

В клетку пишется наименьшее из остатка запаса и остатка потребности, исчерпанная строка или
столбец вычёркивается. Если кончились оба сразу (**вырожденный** случай), вычёркивается строка
(последняя - нет, тогда столбец), а во втором остаётся 0: позже туда пишется перевозка 0 -
**базисный ноль**. Поэтому заполненных клеток всегда ровно `m + n - 1`.

Два места, где ответ зависит от правила, вынесены на экран:

- **нули фиктивной строки или столбца** в методе минимальной стоимости: по умолчанию в
  последнюю очередь, переключателем - первыми, как самые дешёвые. От этого меняется ответ
  почти во всех вариантах (вариант 2: 2870 или 2990);
- **равные стоимости**: в 13 вариантах из 27 другой выбор среди равных клеток даёт другую
  сумму (вариант 1: 3280, а могло быть 2830 или 3330). Под планом перечислены все суммы,
  которые могли получиться, - их находит перебор всех таких выборов (на больших таблицах он
  обрывается на 20 000 состояний, тогда в конце написано «и другие»).

Для каждого метода выводятся итоговая таблица, сумма `Z` по слагаемым и раскрывающиеся шаги:
почему взята эта клетка, сколько груза, что осталось, что вычеркнуто.

## Ключи входа

Ключ вида `ABCD-EFGH-JKLM` даёт доступ к выбранным вкладкам **на одном устройстве**: телефоне с
приложением или браузере с сайтом. Выдаёт ключи владелец в админке.

| Что | Как работает |
|---|---|
| Устройство | телефон опознаётся по `ANDROID_ID` (на сервер уходит его SHA-256), он переживает переустановку; браузер - по cookie, которую ставит сервер |
| Ключ занят | на втором устройстве - отказ, пока владелец не нажмёт «Отвязать устройство» |
| Вкладки | видны только разрешённые; изменение в админке доходит до устройства в течение минуты |
| Отключение | с интернетом выкидывает в течение минуты: проверка при запуске, при возврате в приложение, раз в минуту и перед расчётом. Решение с экрана убирается, введённые таблицы остаются на устройстве |
| Без интернета | приложение работает 3 дня после последней удачной проверки; время считается от загрузки телефона, перевод часов назад его не продлевает |
| Подбор | 12 знаков из 32 - 60 бит; после 10 неверных ключей за минуту с одного адреса - пауза |

Где проверяется: на сайте - на сервере, перед каждым методом расчёта (`@RequiresTab`), в
приложении - в Java (`AccessGuard`), перед каждым вызовом из страницы. Сама страница доступ
только показывает.

**Связь.** Приложение ходит на сервер по https с сертификатом, зашитым в APK
(`network_security_config`), и больше ни с кем соединиться не может: ни чужой сервер с
поддельным ответом, ни телеметрия библиотек. Сайт открывается по http: ключ, введённый на нём в
чужом Wi-Fi, можно подсмотреть, поэтому он привязан к браузеру и отключается в админке.

**От чего это не защищает.** Расчёт идёт на телефоне, а исходники открыты: APK можно переделать
или собрать без проверки. Версии до 1.5.0 ключа не спрашивают. Отключённый человек без интернета
может пользоваться до трёх дней; перезагружая телефон и каждый раз выставляя часы чуть позже
прошлого запуска, он растянет срок сильнее. На сайте так не получится: там считает сервер.

### Админка

Адрес - `/admin/` того же сайта, **только по https** (по http - отказ). Сертификат свой, поэтому
браузер один раз предупреждает.

- **Первый вход.** Пароля в коде нет. При первом запуске сервер пишет одноразовый код в
  `admin-setup.txt` в папке данных; страница, открытая как `/admin/#setup=код`, предлагает
  придумать пароль (от 8 знаков). Второй раз задать пароль нельзя.
- **Дальше** - вход по паролю на 7 дней. Пять неверных паролей с одного адреса - пауза 15 минут.
  Хранится только хэш (PBKDF2, 600 000 повторов).
- **Забыт пароль**: на сервере удалить строку таблицы `admin` и перезапустить службу - появится
  новый одноразовый код, ключи останутся.
- **Ключи**: создать (кому, вкладки), скопировать, изменить, отключить и включить, отвязать
  устройство, удалить, история (последние 200 событий). Видно устройство: модель, версия
  системы и приложения, последний вход. Время московское.

Ключи лежат в базе SQLite (`keys.db` в папке данных, `MULTIFLOW_DATA`, по умолчанию `data` в
рабочей папке). Папка закрыта от других пользователей сервера, выкладка новой версии её не
трогает. Ключи хранятся целиком, чтобы владелец мог скопировать их снова; номера устройств,
токены и входы в админку - только хэшами. В журнале ключи видны как `ABCD-****-****`, токенов,
паролей и номеров устройств там нет и на `LOG_LEVEL=debug`.

## Заполнение по фото

Кнопка **«По фото»** есть у матрицы во вкладке «Поток», у каждой из трёх таблиц во
вкладке «Размещение» (производство, сбыт, план) и у таблицы во вкладке «Транспортная» - её
снимают целиком, как в задании: стоимости, справа запасы, снизу потребности. Порядок такой:

1. «Камера» или «Галерея». Снимает системная камера, поэтому разрешение на камеру
   приложению не нужно; галерея тоже открывается без разрешений.
2. Снимок распознаётся **на телефоне** библиотекой Google ML Kit
   (`com.google.mlkit:text-recognition:16.0.1`, модель лежит внутри APK). Интернет и
   сервисы Google не нужны. Мелкий снимок перед распознаванием увеличивается до 2400 px по
   длинной стороне (не больше чем втрое): на мелких ML Kit теряет одиночные цифры.
3. Ядро (пакет `photo`) собирает из найденных слов таблицу:
   - каждое слово приводится к числу: «1O5» -> 105, «35.000» -> 35000, «-» - прочерк;
     подписи («Вид», «руб.») отбрасываются;
   - строки - цепочки слов, перекрывающихся по высоте (держится и на снимке под углом),
     столбцы - слова, перекрывающиеся по ширине; «35 000» с пробелом - одно число;
   - слипшиеся числа соседних клеток («10» и «210» -> «10210») делятся по широким промежуткам
     между знаками, число, найденное дважды на одном месте, берётся один раз;
   - строка 1, 2, 3... сверху и столбец 1, 2, 3... слева - номера, они не подставляются
     (узнаются, даже если распознавание потеряло часть номеров);
   - одиночные числа по краям (номер страницы, «Таблица 1») отбрасываются.
4. **Предпросмотр**: фото, распознанная таблица и что с ней сделано. Нераспознанные клетки
   показаны «?», исправленные распознаванием - оранжевым. Кнопки «Подставить»,
   «Переснять», «Закрыть».
5. «Подставить» выставляет размер и вписывает числа; подставленные клетки подсвечены,
   работает «Вернуть как было». План задаёт число видов (предприятий при нужде
   становится не меньше).

Во вкладке «Поток» пустая клетка законна - «ветви нет», и её не отличить от
нераспознанной цифры. Поэтому клетки сверяются с зеркальными: нераспознанная c(i,j)
берётся из c(j,i), а если в паре распознаны разные числа, берётся число над диагональью и
обе клетки выделяются.

**Что показала проверка на эмуляторе** (сгенерированные снимки таблиц, не настоящие фото):

| Снимок | Результат |
|---|---|
| производство, печатное, с номерами строк и столбцов | 15 из 15 |
| сбыт, печатное, без номеров и без линий | 15 из 15 |
| план с «35 000», «160 000» | 6 из 6 |
| матрица «Поток» 7 × 7 с прочерками на диагонали | все 12 ветвей верно |
| производство, рукописный шрифт, под углом, с тенью | 11-12 из 15, одна цифра неверно (29 -> 24) |
| матрица «Поток», рукописный шрифт | 7 ветвей из 12, остальные пришли пустыми |
| «Транспортная», вырезка из задания крупно (варианты 10, 22, 25) | 29 из 29 |
| «Транспортная», вырезка шириной в лист вместе с номером варианта, мелко | 27 из 29, одно число неверно (160 -> 60) |

Печатные таблицы распознаются хорошо, рукописные - заметно хуже: неверную цифру нужно
поправить руками после подстановки, а в матрице «Поток» - сверить пустые клетки с фото.

**Цена.** Библиотека распознавания увеличила APK со 170 КБ до ~19 МБ: модель и её код
лежат внутри, отдельно под каждую архитектуру процессора (оставлены arm64-v8a и
armeabi-v7a - телефоны, x86_64 - эмуляторы). ML Kit сам добавляет разрешение на интернет
ML Kit сам добавляет
службы для отправки своей телеметрии - они убраны в манифесте, а настройки сети не дают
соединиться ни с кем, кроме сервера ключей. Распознаванию сеть не нужна.

## Как собрать и проверить

Нужны JDK 17 или новее, Maven и Android SDK (platform 36). Путь к SDK -
в `android/local.properties`:

```
sdk.dir=C:/путь/к/Android/Sdk
```

### Тесты ядра

```bash
mvn test
```

Уровень логов в тестах - переменная `LOG_LEVEL` (`debug`, `info`, `warn`, `error`).

### Сборка APK

Адрес и сертификат сервера ключей в репозиторий не входят, их берут из
`android/server.properties` (файл в `.gitignore`):

```
server.url=https://адрес-сервера
server.certificate=server.crt
```

`server.crt` - сертификат сервера в PEM, путь от папки `android`. Без этого файла приложение
соберётся, но ввести ключ будет негде. Другой файл (например, для проверки на эмуляторе) -
параметром `-PserverProperties=путь`.

```bash
cd android
```

```bash
.\gradlew.bat assembleRelease
```

Готовый файл - `android/app/build/outputs/apk/release/app-release.apk`, около 17 МБ
(почти всё - библиотека распознавания фото). Релиз подписан отладочным ключом
`~/.android/debug.keystore`, тем же, что и прежние версии: иначе он не встал бы поверх них.
Этот файл нужно сохранить. Для проверки через DevTools собирается `assembleDebug`.

### Установка на телефон

На телефоне включить **Параметры разработчика → Отладка по USB**, подключить кабелем
и подтвердить запрос. Затем:

```bash
adb install -r android/app/build/outputs/apk/release/app-release.apk
```

APK можно и просто перекинуть на телефон и открыть - потребуется разрешить установку
из неизвестных источников.

На **Android 10** после обновления с версии 1.4.2 и старше (у них не было доступа в интернет)
система разрешает приложению интернет только после перезагрузки телефона. Приложение само
просит об этом, если ключ не вводится. На Android 11 перезагрузка не нужна.

### Логи

Все строки приложения, ядра и страницы идут в logcat под тегом `MultiFlow`:

```bash
adb logcat -s MultiFlow
```

Подробный уровень включается без пересборки, потом приложение нужно перезапустить:

```bash
adb shell setprop log.tag.MultiFlow DEBUG
```

## Сайт

Тот же экран, что в приложении, открывается в браузере, в том числе в Safari на айфоне.
Вкладки считаются как в APK, вход - по такому же ключу. Кнопок «По фото» на сайте нет: распознавание работает
только в Android-приложении (ML Kit), в браузере его нет. В Safari сайт можно положить на
экран «Домой» («Поделиться» → «На экран Домой»): появится значок приложения, и сайт
откроется без адресной строки. Интернет при этом всё равно нужен - считает сервер.

Страница обращается к тем же адресам, что подменяет `android-bridge.js` в приложении, и
получает тот же JSON из ядра:

| Адрес | Что делает |
|---|---|
| `GET api/example`, `POST api/solve` | вкладка «Поток»: пример и расчёт |
| `GET api/placement/example`, `POST api/placement/solve` | вкладка «Размещение» |
| `GET api/transport/example`, `POST api/transport/solve` | вкладка «Транспортная»: 27 вариантов и расчёт |
| `POST api/access/activate`, `POST api/access/check` | ввод и проверка ключа (сайт и приложение) |
| `api/admin/*` | админка: вход и ключи, только по https |
| `GET api/health` | жив ли сайт и какая версия выложена |
| `POST api/client-log` | предупреждения и ошибки страницы - в журнал сервера (не больше 30 в минуту с адреса) |

Ошибки ввода - ответ 400, сбой расчёта - 500, тело `{"title": "...", "detail": "..."}`, как
у моста в приложении. Нет доступа - 401 (нужен ключ) или 403 (нет такой вкладки), в теле ещё
`reason`: `none`, `disabled`, `unbound`, `deleted`, `tab`. Тело запроса больше 64 КБ сайт не принимает.

### Запуск на компьютере

```bash
mvn -B package
```

```bash
java -jar web/target/multiflow-web.jar
```

Затем открыть <http://localhost:8091>. По умолчанию сайт слушает только `127.0.0.1`; чтобы
открыть его с телефона в той же сети Wi-Fi, перед запуском задать `SERVER_ADDRESS=0.0.0.0`.
Порт меняется переменной `SERVER_PORT`, уровень логов - `LOG_LEVEL`
(`debug`, `info`, `warn`, `error`). База ключей создаётся в папке `data`, другая папка -
`MULTIFLOW_DATA`. Одноразовый код первого входа в админку - в `data/admin-setup.txt`, адрес -
`http://localhost:8091/admin/#setup=код` (на своём компьютере админка открывается и без https).

### На сервере

Сайт работает службой systemd от отдельного пользователя без прав root и слушает
`127.0.0.1:8091`. Снаружи перед ним стоит nginx: он передаёт сайту адрес посетителя
(`X-Real-IP`), протокол (`X-Forwarded-Proto` - по нему закрыта админка на http) и номер запроса
(`X-Request-Id`), по которому строки одного запроса находятся в журнале. По http открыт сайт, по
https со своим сертификатом - он же, админка и адреса для приложения. Новая версия выкладывается так: собрать jar (вместе с тестами), скопировать на
сервер, перезапустить службу и дождаться ответа `api/health`; если сайт не поднялся за
60 секунд, вернуть прежний jar. Скрипты выкладки и настройки конкретного сервера в
репозиторий не входят.

Логи на сервере:

```bash
journalctl -u multiflow -f
```

После старта в журнале - версия, адрес и пробный расчёт встроенного примера
(`self-check ok: 6 steps`), дальше по строке на каждый запрос. Логи ядра идут в тот же
журнал с тем же номером запроса `rid`.

## Проверка расчёта

В модуле `core` 89 тестов. Для вкладки «Поток»:

- на 500 случайных сетях от 2 до 10 вершин итоговая таблица совпадает с **полным
  перебором всех разрезов** - проверка, в которой нет ни строчки кода решателя;
- каждая ветвь дерева - минимальный разрез между своими концами;
- на каждом шаге таблица R - исходная матрица целиком, строки 1…n по порядку (склейки нет);
  пары и потоки шагов примера закреплены: 1-2 = 9, 1-3 = 18, 2-4 = 18, 3-5 = 19, 4-6 = 24,
  6-7 = 21;
- на каждом шаге сумма ветвей разреза равна потоку, а найденные пути складываются в поток
  и после них путей от S к T не остаётся;
- на каждом шаге R - Xst клетка в клетку равна таблице после вычитания, Xst(i,j) = -Xst(j,i),
  поток по ветви не больше её пропускной способности, из S выходит поток, в T входит, в
  остальных вершинах сколько вошло, столько и вышло; Xst шага 1 примера сверена поклеточно;
- несвязная сеть, изолированная вершина, сеть из двух вершин;
- отказ на несимметричной матрице, отрицательных и слишком больших числах, пустой сети.

Для вкладки «Размещение»:

- пример из пособия: ответ 7892 и все промежуточные числа - матрица, минимумы строк,
  назначения и правила, по которым они сделаны, линии, минимум 160, матрица после
  модификации - совпадают с книгой; с напечатанными в книге числами ответ 8137;
- на 2000 случайных задачах от 2 × 2 до 8 × 8 (с узкими диапазонами чисел, чтобы было
  много нулей и ничьих) и на трёх задачах 10 × 10 прибыль совпадает с **полным перебором
  всех размещений**. Число других оптимальных размещений тоже совпадает с перебором.
  В этом прогоне встречаются и выбор нуля, и замена лишних линий, и достраивание
  назначения перебором - тест проверяет, что все три случая действительно возникают;
- на каждой итерации: после редукции в каждой строке и столбце есть ноль, все нули
  отмечены, линий наименьшее число и они закрывают все нули, модификация сделана верно,
  отрицательных чисел нет;
- видов столько же, сколько предприятий; вся продукция убыточна; все прибыли равны
  (список других размещений и остановка перебора на 10! вариантах);
- отказ на видах больше, чем предприятий, отрицательных, слишком больших и дробных
  числах, нулевом объёме, таблицах не того размера.

Для вкладки «Транспортная»:

- на всех 27 вариантах суммы обоих методов (с обоими правилами фиктивных клеток) и оптимум
  совпадают с отдельной программой на Python; оптимум там считал симплекс-метод (scipy, HiGHS);
- на 1000 случайных таблицах до 10 × 10: северо-западный угол совпадает с независимым расчётом
  через накопленные суммы; на каждом шаге минимальной стоимости клетка действительно самая
  дешёвая из невычеркнутых, а из равных - с наибольшей перевозкой; оптимум совпадает с потоком
  минимальной стоимости; все планы допустимые, заполнено ровно `m + n - 1` клеток без циклов;
- на 300 маленьких таблицах оптимум совпадает с полным перебором планов, на 400 - с перебором
  совпадает и ответ, единственный ли оптимальный план;
- шаги варианта 1, вырожденный план с базисными нулями, ничьи, список других сумм (сверен с
  перебором на Python), остановка перебора, закрытая модель, наибольшие числа;
- отказ на размерах и числах вне пределов.

В модуле `web` 45 тестов. Сайт целиком:

- ключи: без ключа не считает ни один метод расчёта (проверяется и то, что отметка стоит на
  каждом), необычная запись адреса проверку не обходит; браузер и телефон занимают ключ, второе
  устройство получает отказ, из восьми одновременных вводов проходит один; отключение,
  включение, отвязка, удаление, смена вкладок; копия токена на другом устройстве не действует;
  пауза после неверных ключей; история;
- админка: одноразовый код, вход, пауза, срок сеанса, выход; по http и с чужой страницы - отказ;
  все действия с ключами;
- ни ключ, ни токен, ни пароль, ни номер устройства не попадают в журнал на самом подробном
  уровне; ключи переживают перезапуск; базу более новой версии старая не трогает;
- отдаются страница и скрипты, `api/health` отвечает версией;
- пример «Потока» после `api/solve` даёт ту же итоговую таблицу, что ядро, шаг 2 - пара 1-3
  на таблице 7 × 7;
- пример «Размещения» даёт 7892 тыс. руб.;
- несимметричная матрица, дробная клетка, не JSON, нет поля `capacities` - ответ 400 с
  заголовком и подробностью; тело больше 64 КБ - ответ 413;
- журнал ошибок страницы принимает записи и с 31-й в минуту с одного адреса отказывает.

Для заполнения по фото (слова раскладываются по координатам так, как их отдало бы
распознавание):

- слова -> числа: буквы вместо цифр, тысячи через точку и пробел, скобки, прочерки, подписи;
- таблицы с номерами строк и столбцов и без них, под углом и с дрожанием, номера по центру
  над числами, прижатыми к краю, номера с пропусками;
- пропущенная клетка, лишние числа по краям снимка;
- матрица «Поток»: прочерки на диагонали, только верхний треугольник, разные числа в паре,
  клетка из зеркальной;
- «Транспортная»: все 27 вариантов как на снимке, номер варианта сбоку, под углом, с номерами
  строк и столбцов, число в пустом углу, пропущенная клетка;
- слипшиеся числа соседних клеток и число, найденное дважды;
- отказы: нет чисел, матрица не квадратная, видов больше, чем предприятий, в плане не два
